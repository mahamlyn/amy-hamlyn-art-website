# Amy Hamlyn Art

A lightweight Flask website for an artist portfolio and studio journal.

## Features
- Modern landing page with elegant, editorial styling
- About section written as Markdown
- Gallery with image cards and artwork descriptions
- Upcoming exhibitions section
- Blog section powered by Markdown posts
- Easy maintenance: update content in the `content/` folder without editing templates

## Project structure
- `app.py` – Flask app and content loaders
- `content/about.md` – About page content
- `content/gallery/*.md` – gallery item content
- `content/exhibitions/*.md` – exhibition information
- `content/blog/*.md` – blog posts
- `templates/` – HTML templates
- `static/` – CSS and image assets

## Run locally
1. Open a terminal in this folder.
2. Create a virtual environment if needed.
3. Install dependencies:
   `pip install -r requirements.txt`
4. Start the app:
   `python app.py`
5. Open the site in your browser at `http://127.0.0.1:5000`

Flask routes are protected against CSRF on state-changing requests. Set `FLASK_SECRET_KEY` to a stable, private value when running Flask outside local development; the application generates a temporary key when it is unset.

Markdown content is sanitized before rendering. The development entry point runs with Flask debug mode disabled.

## Updating content
Add or edit Markdown files in `content/`:
- About: `content/about.md`
- Gallery items: `content/gallery/*.md`
- Exhibitions: `content/exhibitions/*.md`
- Blog posts: `content/blog/*.md`

Each Markdown file can include YAML front matter like:

```yaml
---
title: "Example title"
date: "12 October 2026"
excerpt: "Short summary"
---
```

This keeps the site easy to maintain and update without needing web development knowledge.

## Quality analysis and CI

The manual GitHub Actions workflow builds the Flask site into static files, runs a SonarQube security scan, creates or updates one GitHub issue per unresolved finding, and deploys to the configured Cloudflare Pages project only if the build and SonarQube Quality Gate pass.

- Workflow file: [.github/workflows/build.yml](.github/workflows/build.yml)
- Project properties: [sonar-project.properties](sonar-project.properties)
- Trigger: manual execution via GitHub Actions (`workflow_dispatch`)
- Build output: `dist/`, generated by `scripts/build_static_site.py`
- Security scan: runs on the configured self-hosted runner
- Finding tracking: unresolved findings become deduplicated GitHub issues, labeled by severity and type, with rule guidance, source context, and flow locations where available
- Deployment: Cloudflare Pages at `https://amyhamlynart.pages.dev`, after the SonarQube Quality Gate succeeds

Configure the `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `SONAR_TOKEN`, and `SONAR_HOST_URL` repository secrets. The workflow token needs the repository `Issues: write` permission. The Cloudflare token needs permission to edit Pages projects, and the self-hosted runner must be online for the security scan. The static export uses `/` as its base path for the Cloudflare domain.
